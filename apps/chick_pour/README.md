## 与 SPEC 的落地差异(均有理由)

1. **家可读性加强批(2026-07-12 实机反馈"小鸡的家不够明显",SPEC 外新增)**:
   大拱门(奶油门框 + 深棕门洞,跨骑门区全高,原 6px 细条门洞否决)、门口沙色**门垫**
   (伸进场地,与池塘浅滩缺口对仗的"从这儿进"地面邀请)、两家门口**住户脸招牌**
   (黄小鸡/白小鸭大圆脸,不识字 → 语义靠脸,兼防 §11② 分拣认知卡壳)。
2. **探头小脸挪到屋顶天窗条**:SPEC §5.3 原文"鸡窝窗口冒鸡头"在屋身;屋身让位给大门
   + 招牌后挪上屋顶(池塘侧不变,仍在水面高光带下方)。
3. **撞墙音节流是全群共用 250ms 窗口**(`WALL_BUMP_SND_COOLDOWN_MS`,SPEC 只说"节流"):
   10 只可能同帧蹭栅栏,按只节流仍会机枪音;挤压视觉不节流(每只自己的因果)。
4. **`SHAKE_COOLDOWN_MS 2000`**(SPEC 值;busy_knobs 实际定案 1500,本作彩蛋音效更长取 2000)。
5. **ATTRACT 醒来判定** = 水平两轴合成幅度 `sqrt(ax²+ay²) > 0.22g`(与屏轴映射无关,平放噪声 ~0.02g)。
6. **SCATTER 不设独立状态**:重散是 PARTY 倒计时归零时的一次性动作(散点约束随机 + 拒绝
   采样 + 校验断言,失败退预置网格,永不失败)。
7. **`GATE_DEPTH` 10→13(SPEC 外新增,§13.4)**:实施图纸批时发现 `ANIMAL_R` 8→11 后
   旧 `GATE_DEPTH=10 < ANIMAL_R=11`,破坏"动物中心先进门区判定、才可能碰家墙"的不变量
   (~1px 窗口内身体先蹭墙、门判定才接管)。按原设计 2px 余量补到 13。`tools/preview.py
   check_layout()` 加了 `GATE_DEPTH > ANIMAL_R` 断言防回归。
8. **鸭池"水面高光"改成按门朝向镜像绘制(SPEC 外发现的隐藏 bug)**:旧公式假设门恒在
   家的 x0 侧(只对图纸 A/C 的池塘 face=LEFT 成立);图纸 B 的池塘 face=RIGHT,不镜像
   会被门框盖掉约 60%(实测只剩 ~7px 可见)。`scene.c draw_home_layer()` 与
   `tools/preview.py draw_home()` 都已按 `face` 镜像重算。
9. **重散网格兜底改图纸感知(SPEC 外发现的隐藏 bug)**:旧 `grid_layout()`"固定两行
   y 偏移 ±34"假设家在 `cy=120`;图纸 C 的鸡窝 `cy=78` 时,固定行 y=86 恰好扫过新门区
   ——网格兜底摆出来的动物可能直接出生在门判定区里。新增 `scatter_grid_fallback()`
   (栅栏内粗网格扫描 + 复用约束随机同一套合法性判据)专供 `flock_scatter` 用;
   `flock_init` 的开局摆位仍用旧函数(boot 恒为图纸 A,继续安全,故意不改)。

## 图纸批实现要点(SPEC §13,2026-08-10)

- **图纸运行时化**:`HOUSE_RECT/POND_RECT/HOUSE_GATE/POND_GATE/HOUSE_FACE/POND_FACE/
  CORNER_BUSH` 从 `extern const` 改成 `extern` 可写全局量,`scene_apply_blueprint(idx)`
  切图纸时算好写入,`flock.c` 原样直接读——这样门判定/碰撞/布点代码基本不用改,只有
  两处"写死方向"的代码要改(门弹出方向、网格兜底布点,见下)。
- **换图纸 = 整屏重画一次**(合根 `CLAUDE.md` §6.1 允许的"进关/换场景"档位):`scene.c`
  新增一个专用容器 `s_layout`(家×2+灌木×4+探头小脸),`lv_obj_clean()` 后重画,不碰
  栅栏/草地(图纸无关,只在 `scene_init` 画一次)。派对弹跳(`scene_party_bounce`)引用
  的家部件句柄在每次重画时刷新,时序上派对弹跳总是在换图纸**之前**完成(先派对、
  `PARTY_HOLD_MS` 倒计时归零才换图纸),不会有跨重绘的悬空指针。
- **加载校验 `layout_verify()`**:仿 `tools/preview.py check_layout()` 逐条翻译成 C
  (家不出栅栏/两家外墙不重叠/门朝场地/灌木不压家不堵门外进场点/粗网格 flood fill
  两门互相走得到),失败 `ESP_LOGE` + 回退图纸 A,不 abort。flood fill 用的网格缓冲
  (`FLOOD_COLS×FLOOD_ROWS` = 4941 格)是 **`static`(BSS),不是栈上数组**——
  它会在 `party_tick()`(`game_task`)里调用,栈上放不下这么大的数组(根 `CLAUDE.md`
  §11 关于任务栈预算的坑,这次是同一类问题的新现场)。
- **轮换**:开机恒图纸 A,每轮派对后 `game_state.c` 依次 `(当前+1) % 3`。**不掷骰子、
  也不做跨开机的持久轮转** —— 2026-08-10 那版用 NVS 存开机计数,是围着"随机数不随机"
  这个错判打的补丁,根因修掉后没有存在理由,2026-08-13 连同 `kv_store` 依赖一起删除。

### 🔴 "玩多久都只有一张后院"的真因(2026-08-13 修复)

`layout_verify()`(原 `scene_verify()`)里 flood fill 的**填表**循环写成了

```c
for (int c = 0; c < FLOOD_COLS && start < 0; c++)   // ← start<0 本意是"种子找到就别再找了"
```

`start < 0` 挂在**外层**,于是找到第一个空地格就把整张网格的填表一起终止了:81 列只填
了前 7 列,其余 74 列保持 BSS 的 `0` = **当成障碍**。flood fill 只能在最左那条 x=24 的
窄缝里爬,两个门外进场点(列 21 / 列 60)自然"走不到"——**A/C/B 三张全判失败,每次
都回退图纸 A**。屏幕上看就是"图纸永远只有一张",和"设计如此"分辨不出来。

修法与配套(三条都是防它再来):

1. 填表循环填满整张网格;种子改从**家 0 的门外进场点**起(要验的性质本来就是"这个
   门口能不能走到那个门口";拿扫描序第一个空地格当种子,可能落进角落死水洼,把本来
   能玩的图纸判死——与本 bug 同一类"校验器自己制造失败")。场地连通率 <80% 只
   `ESP_LOGW` 告警、**不判失败**(4px 粗网格的假死角很常见,再加一道硬闸门就是重蹈覆辙)。
2. **几何与校验搬出 `scene.c` 成 `main/layout.c`**(不依赖 LVGL/BSP),主机能直接编译
   真身:`tools/verify_host.sh` → 三张图纸逐一 `layout_verify()` + `layout_apply()`
   必须真的切过去(不是悄悄回退 A)+ **`flock_scatter` 布点 3 图纸 × 40 个随机种子**
   (不出栅栏/不进墙/不进门区/不压灌木/不重叠,合法性由测试独立复算,不复用 flock.c
   自己的 `scatter_validate`),退出码 0 才算过。**改几何/图纸/校验/布点先跑它再烧板。**
   —— `tools/preview.py check_layout()` 是**平行的 Python 翻译**,它一直是过的,两份
   实现各说各话,只有实机才暴露;`verify_host.sh` 测的是要烧进板子的那份代码。
3. `scene_init()` 开机调 `layout_selftest()`,把三张图纸全跑一遍并打一行日志
   (`I (xxx) layout: 图纸自检:3/3 通过`)。护栏自己坏掉时,唯一能当场戳穿的就是这行。

## 实现要点(跨任务纪律,仿平台先例)

- **捕获所有权交接**(§5.3):`flock_step` 置 `active=false` + 事件 → game_task **即时计数**
  (不等动画)→ `critters_capture` 起 lv_anim"蹦进门"(直线插值 + 抛物弧 + 缩到 44%),
  完成回调只隐藏自己的 LVGL 对象,不碰游戏状态(busy_knobs 小鸟影子变量纪律)。
- **脉冲三兄弟**(挤压/摇头/小跳):反馈侧只写计数,`critters_update` 在 game_task 帧循环里
  推进;摇头用 translate_x、小跳用 translate_y,与 `set_pos` 互不打架。
- **弹出节流**:物理每次照弹(flock),反馈每只 300ms(game_state 时戳)。
- **省电**:core2_sleep 全托管(纯 IMU 玩法无 kick);PARTY 态 `nap_eligible=false`;
  ATTRACT/PLAY 可打盹,唤醒回当前进度(归家的不放出来)。
- **音阶进度**:归家第 n 只播五声音阶(C 宫)第 n 音 + 叽(高双音)/嘎(低双音)前缀,
  单笔 `audio_fx_play_notes`(~290ms < 400ms 合成上限)。
