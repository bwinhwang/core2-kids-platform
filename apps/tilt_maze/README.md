## main/ 结构

```
main/  app_main.c(core2_board_init 一键 bring-up + 起状态机)
       game_state.c(60Hz 任务 + 状态机 ATTRACT/PLAY/WIN;省电托管给 core2_sleep)
       physics.c · maze.c(关卡 + BFS 校验 + 滑行碰撞)· render.c(三层 + 特效)
       feedback.c(四通道编排器)· parent_menu.c · tuning.h
```
- **任务/队列**:game_task(60Hz)读 IMU→物理→碰撞→渲染→发事件;feedback/audio/haptics/ledstrip 各自事件驱动消费队列,**不阻塞 game_task**(符合 §3.2)。
- **免校准**:无零点/校准概念,`physics_set_position` 只复位 pos/vel;低通滤波首帧样本自预热。
- **打盹/唤醒**:游戏侧每帧 `core2_sleep_feed()` 喂加速度即可;机制/踩坑见根 `CLAUDE.md` §7(电源/休眠/背光)。

## 绝对零点,免校准(2026-07-02 设计定案,推翻 §8.2)

**定案**:删除整个校准机制。"平"= 屏幕平面与地面平(重力绝对参考),规则永远一致。

**设计依据(用户拍板)**:游戏目的就是让孩子学会控制设备——把设备端平正是要教的东西,物理滚珠迷宫玩具就是这个范式(它们从不"校准"到握姿)。原 §8.2 姿态校准替孩子做了他能自己学会的动作,代价是:①同一物理倾斜在不同会话里作用不同(违背"因果一致"第一性原则);②引入隐藏的、每次都变的参考系;③滋生零点污染 bug。斜着拿球就往下滚 → 孩子自己调整设备对抗,这就是游戏本身。

**技术前提(已实机验证)**:板子加速度计偏置须小于死区 0.06g。本机平放实测 `x=-0.023 y=-0.007 z=1.065,漂移 0.001g` —— x/y 偏置不到死区一半,余量充足;z 偏差不影响玩法(只用 x/y)。

**落地变更**:
- 删 `ST_CALIBRATE` 态与 `calibrate_tick`、`physics_calibrate()`、`physics_t.zero`;ATTRACT 倾斜触发**直接进 PLAY**;
- 删家长菜单"Recal"按钮与 `game_state_request_recalibrate()`(用户明确不要修正入口);
- 删 tuning:`CALIB_*`、`IDLE_STILL_THRESH`;
- 低通滤波改为首帧样本自预热;
- **保留**:减除式死区(见下)、速度封顶、轴映射。
- **已否决**:静止自回零(偷偷移动"平"违背一致性原则)、NVS/菜单偏置修正(本机余量充足)。

**状态**:✅ 已实机验证(2026-07-02 烧录确认)。手感若偏慢,调 `TILT_GAIN` 1800→~2000,勿动死区;斜着拿球向下滚属预期。

### 根因记录:IMU"平放单向慢爬"(2026-07-02,已随免校准修复)

**症状**:有时平放机身,球仍以 ~20px/s 匀速朝固定方向爬。**根因不是 IMU 硬件**:
1. **校准零点被"开始手势"污染(主因,免校准后已消失)**:旧 `calibrate_tick` 从进状态第 1 帧无条件采样,离开 ATTRACT 的倾斜手势把零点拖偏 ≈0.06g(恰好一个死区)。
2. **硬死区悬崖(放大器,已改减除式)**:残余一旦过线(0.06g)就吃全额增益 → ~21px/s 匀速爬。

**保留的修复 · 减除式死区**:只把超出死区的部分交给增益(`(tmag−死区)/tmag` 缩放),消除"过线即全额恒力"的悬崖——零点即使略有污染,残余小力也会被阻尼压住。**注意**:减除式让小倾斜有效力整体减小 0.06g,手感略"重";偏慢时微调 `TILT_GAIN`,勿动死区本身。

## 巡逻怪搬进环路,改绕圈走(2026-08-03 七写,用户实机指着 L7 的方形环回提的)

**定案**:巡逻怪从"两点直线往返"升级为"沿直角折线路径走",并新增 `loop` 走法——沿环单向绕圈、不停。**每关最多 2 只**(`MAZE_HAZARDS`)。

**为什么这是难度的真正来源(而不是又一次加数量)**:六写把怪加到 14/16 关,实机仍嫌简单。根因不是数量是**位置**——
直线怪整段来回扫 1 格窄走廊,**没有绕路就等于永久墙**,所以五写起就被 `verify_mazes.py` 强制赶出所有必经通道,只能待在支路上;
孩子沿主路走一遍就通关,压根不用理它。**绕圈怪没有这个约束**:环是图论上的圈,拿掉圈上任意一格,另一条弧仍连通两侧,
所以绕圈怪**不可能把迷宫劈成两半**,只会轮流给圈上每格投下 ~1/n 圈时长的、全程可见且周期恒定的阴影。于是它可以正大光明
站在必经路上,玩法从"躲开杵在角落的怪"变成"**看准它转到对面,趁机穿过去**"。

顺带救活了另一样东西:16 关每关本来就有 1~2 个环(四写留的"给选路而非对错"),此前是**无差别装饰**——两条弧都通、选哪条都一样。
放进绕圈怪后,"走哪条弧、什么时候进"第一次有代价。

**怪位分布(七写定案,取代上表)**:

| 关卡 | 怪 | 备注 |
|---|---|---|
| L1 / L10 / L12 / L16 | **2 只** | 本袋难度顶;L10 是 1 绕圈 + 1 直线(让一关里两种节奏并存) |
| L14 / L15 | 1 只**直线** | 这两关的环里有起点 S,绕圈怪会在重生点上转 → 保留直线怪 |
| 其余 10 关 | 1 只绕圈 | |

> 合计 **14 只绕圈 + 3 只直线,17 只 / 16 关,覆盖 16/16**(六写是 14/16)。绕行方向顺时针 10 / 逆时针 7,别让整袋都朝一个方向转。
> 环周长决定节奏:8 格环一圈 3.6s(多数关)、12 格 5.5s(L9/L11)、L6 的 20 格环 9.1s(覆盖广、像巡逻线而非门卫)。

**新调参旋钮**:`HAZARD_LOOP_SPEED`(tuning.h,与直线怪 `HAZARD_SPEED` 分开)——嫌"等太久才轮到它让开"就调快,嫌"来不及穿"就调慢,**不影响直线怪**。还嫌简单就先动这个,再考虑给别的关补第 2 只。

**速度定案 44px/s**(2026-08-03 用户"再慢一丢丢",两档从 50 同步降到 44,-12%):怪的速度是**可读性**参数不是难度参数——幼儿要先能看清它在往哪转、什么时候会让开,才谈得上"等准时机"。难度该由怪的**位置**(必经路 vs 支路)和**数量**给,不是靠把它调快到看不清。

🔴 **`verify_mazes.py` 里"整条路径当永久墙"那条检查刻意不覆盖绕圈怪**,这不是漏检——按那条查等于把绕圈怪也赶回支路,恰好废掉它唯一的价值。
取而代之的硬约束:环必须首尾闭合、不自交、≥8 格,路径不压 S/H/星/陷阱,同关两只怪路径不重叠;另报告"需等怪让路的咽喉"(设计意图,不是错误)。**看到那条检查没管环时别顺手补上。**

**失败代价**:只退回本关起点(`start_play` 原样重进同一关:球回起点、星星重新可收、每只怪回各自 `pts[0]`、家动画重置——失败后的局面完全可复现,孩子能靠重复练熟),不影响其它关卡进度——比生命值/连续失败惩罚温和,用户拍板起步先这样,视实机反馈再决定要不要加码。

**反馈词汇新增**(跨平台共享组件追加,尾部追加不改动既有值序):`SND_FAIL`(下行双音,不吓人)/`HAPTIC_FAIL`(双短震,区别于单次撞墙)/`LED_FX_FAIL`(柔和暗紫单次起落,非频闪)。**"还差星星"提示**不新增跨组件词汇,复用 `SND_NEAR`(上扬叮铃)+ `HAPTIC_HELLO`(一下轻震),视觉是 app 内新增 `render_hint_stars`(把没收的星放大脉冲闪 3 下)。
